## No HLS

`AGENTS.md` rule 8 and [ADR 0001](../decisions/0001-progressive-mp4-and-isolated-player-clips.md)
require a single progressive 720p H.264/AAC MP4 with fast-start metadata,
delivered over HTTP Range. This block adds no manifest, no segmenting, and no
streaming library. `apps/web/app/coach/games/[game_id]/player.tsx` uses the
browser's own `<video>` element.

## API surface added

| Method | Route | Behaviour |
|---|---|---|
| POST | `/v1/videos/{video_id}/playback-url` | 15-minute signed URL for the coach-only playback object |
| GET | `/v1/videos/{video_id}/timeline` | Signed sprite sheets plus tile geometry |

Both refuse a video the worker has not finished preparing with a `409`
`video-not-ready`, which the processing screen can name, rather than a `404`
that would imply the match does not exist.

## Security properties asserted

- **Rule 4 — players never receive full-match access.** A player gets `404` on
  both routes (`test_a_player_can_never_sign_the_coach_playback_object`,
  `test_a_player_cannot_read_the_timeline`).
- **Object-specific signing.** The signed URL names
  `playback/{video_id}/coach-720p.mp4` and never `originals/`. The key is
  derived from the video's UUID inside the route; no request value reaches it.
- **Fifteen-minute ceiling.** Asserted against `storage.GET_URL_SECONDS`.
- **No key disclosure.** No response body contains `playback_key` or
  `original_key`.
- **Cross-team.** A coach outside the team gets `404`, identical to an unknown
  video.
- **No shell.** ffmpeg and ffprobe run through argument arrays only.
- **Coach-safe errors.** A probe failure names no path; every refusal is an RFC
  9457 problem document.

## Database

`0005_video_ingest` → **`0006_media_playback`**.

Grant-only: it widens `shoulder_worker`'s column-level `UPDATE` on `app.video`
to `playback_key`, `duration_ms`, `width`, `height`, `fps`, and
`first_terminal_failure_at` — the columns Task 11 is the first code to produce.
No table, policy, or index changes, so RLS is untouched and `app.video` keeps
forced row-level security with the `video_worker_*` policies from `0005`.
Downgrade is a matching column-level `REVOKE`, so `status` and `ready_at` from
`0005` survive exactly.

`original_key` still has no `UPDATE` grant on any runtime role.

### One test expectation changed, and why

`test_the_worker_cannot_write_a_storage_key` asserted the worker could write no
storage key at all. Its own docstring named its successor: *"Task 11 widens this
grant when it has a playback object to name."* Migration `0006` is that
widening, so the expectation was stale rather than violated. It was replaced by
two stronger assertions: `original_key` is unwritable by the worker, and the
worker's entire `UPDATE` column set on `app.video` is pinned, so any future
widening has to be deliberate. No assertion was removed or loosened.

## Known gaps

- **Firefox browser tests did not run locally.** Windows Smart App Control
  blocks Mozilla's `lgpllibs.dll` (`LoadLibrary` 4551, "An Application Control
  policy has blocked this file"); a clean Playwright reinstall does not change
  it. No Playwright config was altered and no security policy was disabled.
  GitHub CI runs all three engines on Ubuntu.
- **No Playwright suite for the player yet.** Task 13's transport and scrubber
  are covered by unit tests for the geometry and by typecheck, lint, and build,
  but not yet by a browser test driving the real element. This is the largest
  outstanding item in the block and is named here rather than implied.
- **Playback budgets are not yet measured.** `docs/02-architecture.md` sets
  first frame < 2.5 s and random seek < 1.5 s p75. Those need a full-length
  fixture through the real worker and R2; the block's transcode path is proved
  correct but not yet proved fast. ADR 0001 requires measurements before any
  HLS discussion, and none is proposed.
- **`Shoulder Dev` has not received `0006`.** The host is IPv6-only and this
  workstation's path to it is intermittent.
- **The worker end-to-end path is not yet exercised against MinIO.** The
  transcode and thumbnail handlers are registered and unit-tested; a job claimed
  from the queue that reads a real source object and writes a real playback
  object is not yet covered.
