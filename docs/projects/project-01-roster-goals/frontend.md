# Expected Outputs

**`/` (`apps/web/app/page.tsx`)** — resolve the session, call `/v1/me`, redirect
`coach → /coach/roster`, `player →` the neutral signed-in page, no session → `/login`, no
role → the neutral signed-in page. Never infer a role from the route, a cookie, a query
parameter, or client state. An unavailable API grants no product access.

**Coach shell** — desktop navigation with Dashboard, Players, and account. The current
team and season appear once in the shell. "Upload match" is the persistent primary action
and, in this block, is a disabled control with a plain "Coming soon" title rather than a
dead link. Below 1024px the shell collapses to a compact rail or top navigation.

**`/coach/roster`** — compact table: player, number, position, active goal, account state,
next action. Local search only above ten rows. First-use empty state is the bulk paste
area. Paste is parsed by `lib/roster.ts` into a preview table with row-level errors, and
requires explicit confirmation before an all-or-nothing save. Adding one player uses an
inline row or a small dialog. Archive is visually separate from edit and requires
confirmation. Invitation is a secondary action, and the whole workflow is usable with no
email collected.

**`/coach/players/[player_id]`** — player identity and exactly one active goal; when none
exists the primary action is "Set a goal". Closed goals in a collapsed section. Leave a
clearly marked empty region for the evidence timeline and reflections; do not build them,
and do not render a placeholder that implies data exists.

**`lib/roster.ts`** — pure parser, no React and no I/O: takes pasted text, returns rows of
`{ display_name, jersey_number, position, errors }` for `name, number, position` input.
Handles a trailing comma, missing optional fields, a blank line, a duplicate jersey inside
the paste, a number outside 0–99, and a name outside 1–80 characters. Server validation
stays authoritative; this parser only makes the preview honest.

**States** — loading reserves final geometry with skeletons only for genuinely pending
content, never a full-screen spinner. Errors state what happened, what was preserved, and
the next action, with no provider name or code. Forbidden and not-found share one
not-found surface.

**Prohibited** — no score, rank, percentage, average, trend, chart, KPI card, badge,
streak, or engagement copy anywhere. No `ontology_key` rendered. No player email shown on
the roster; account state is a neutral "Linked" or "Not linked".

# Required Targeted Tests

```
node --test tests/roster.test.mjs
pnpm format:check && pnpm lint && pnpm typecheck && pnpm build
pnpm exec playwright test tests/roster.spec.mjs
```

`tests/roster.test.mjs` covers the parser edge cases listed above. `tests/roster.spec.mjs`
covers the keyboard path through paste → preview → confirm → saved, the inline add row,
accessible names on every control, an `@axe-core/playwright` check on both routes, and no
layout shift when the preview appears. Test at the widths named in
`docs/09-frontend-design-system.md`. The Playwright suite needs a running API and database;
if those are unavailable in your checkout, report it as `not run — API pending` rather
than skipping or weakening a test.
