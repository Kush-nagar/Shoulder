# Expected Outputs

**`services/api/problems.py`** — one small module: a `Problem` exception carrying
`status`, `type` slug, `title`, and `detail`, and FastAPI handlers that render RFC 9457
`application/problem+json` for it, for `HTTPException`, and for `RequestValidationError`
(422). Bodies carry `type`, `title`, `status`, `detail`, `instance` and nothing else.
Never include a player name, email, jersey number, SQL, a SQLSTATE, a token, or a raw
provider message in `detail`. `Cache-Control: private, no-store` on every error response.

**`services/api/schemas.py`** — the models listed in the frozen API contract, with the
stated length and range constraints.

**`services/api/routes.py`** — the ten routes. Rules:

- Every route depends on `authenticated_identity` and runs inside `user_transaction`.
  Never `operator_transaction`.
- Authorization comes from the database. Do not re-derive a role in Python and do not
  trust a client-supplied team, player, or user ID as authority.
- Distinguishing 403 from 404: read the row first through RLS. No row → 404. Row visible
  but the write is refused → 403. Do not leak existence any other way.
- Bulk validates every row, including duplicate jersey numbers within the request and
  against the existing active roster, before any write. `commit=false` → 200, writes
  nothing. `commit=true` with any invalid row → 422 with the same per-row results, writes
  nothing. All valid → one transaction, 201.
- Invite calls `private.link_player_account` and maps its SQLSTATEs: `23505` → 409,
  `22023` → 422, anything else → 503.
- Archive sets `active = false` and `deleted_at = now()`. It never claims erasure and
  never deletes a row. It is idempotent: archiving an already-archived player returns the
  same 200 body.
- Goal transitions follow the frozen table. `active → achieved | paused | retired`;
  `paused → active | retired`; `achieved` and `retired` are terminal. Leaving `active`
  sets `closed_at = now()`; entering `active` clears it. A second active goal is 409, and
  the unique index is the real enforcement — map its `23505` to 409 rather than relying on
  a read-then-write check.
- Keep SQL as `text()` with bound parameters, matching the existing file. No ORM models,
  no query builder, no new dependency.

**`tests/test_api_roster.py`** — one suite covering, at minimum: 401 with no token; 403
for a player calling a coach route on a visible row; 404 for a coach on another team's
player; 409 for a duplicate active jersey, an already-linked player, a second active
goal, and an invalid status transition; 422 for field validation and for a bulk row
error; bulk preview writes nothing; bulk commit with one bad row writes nothing; bulk
commit with all rows valid writes all rows; invite links the account and creates the
membership in one transaction; archive is idempotent. Follow the database-requirement and
skip conventions already used by `tests/test_auth.py` — the suite must not silently pass
when no database is configured.
